# 기준 미달을 남기기

같은 지적을 두 번 받았다면, 첫 번째 지적이 어디에도 남지 않은 것이다.
무엇이 왜 탈락했는지 적어 두면 안목이 쌓인다.
적어 두지 않으면 다음 세션은 같은 실수를 처음부터 다시 한다.

## 순서

1. **무엇이 기준에 못 미쳤는지 한 문장으로 적는다.**
   느낌이 아니라 관찰로 쓴다.
   예: "표의 첫 열이 줄바꿈되어 읽기 어려웠다".
2. **왜 그렇게 됐는지 적는다.**
   증상이 아니라 원인을 찾는다.
   예: "표 CSS 규칙이 아예 없었다".
3. **다음 작업이 실제로 읽는 곳을 고른다.**

| 남길 곳 | 맞는 경우 |
|---|---|
| 테스트 | 코드로 확인할 수 있는 실수 |
| 훅 | 도구 호출 전에 막을 수 있는 실수(금지 명령, 금지 문자, 형식) |
| 설정, 린터 | 형식이나 스타일 규칙 |
| 스킬 | 특정 종류의 작업에서 반복되는 판단 실수 |
| 협업 문서, 프로젝트 지침 | 여러 세션이 함께 지켜야 하는 약속 |
| 메모리 | 사용자 취향, 이 사용자와 일할 때만 해당하는 것 |

강제할 수 있는 곳(테스트, 훅)이 있으면 문서보다 그쪽을 먼저 고른다.
문서는 읽히지 않을 수 있지만, 훅과 테스트는 매번 돈다.

4. **이유를 함께 적는다.**
   규칙만 적으면 다음 사람이 경계 사례에서 판단하지 못한다.
   "왜"가 있어야 비슷한 다른 실수도 막는다.
5. **이미 있는 기록을 먼저 찾는다.**
   같은 내용이 있으면 새로 만들지 않고 고친다.
   틀린 기록은 지운다.

## 남기지 않는 것

- 이번 작업에서만 의미가 있는 것.
- 코드나 이력을 보면 바로 알 수 있는 것.
- 비밀값, 토큰, 개인정보.
