# 에이전트 감독의 네 원칙

에이전트 출력은 대체로 맞고 잘 쓰여 있어서, 다시 볼 이유를 느끼지 못한다.
아래 네 원칙은 그 틈을 막는다.
되돌리기 쉬운 일은 1과 2만, 다른 사람이 결과를 감당하는 일은 넷 모두 지킨다.

## 1. 검증됨을 먼저 정한다

끝난 뒤에 기준을 정하면 어떤 결과든 합리화하게 된다.

- 시작 전에 끝 기준을 적는다.
  해석이 아니라 실체로 쓴다. 테스트 통과, 측정값, 로그, 스크린샷이다.
- 그 실체를 만드는 명령을 함께 적고, 에이전트가 직접 돌려 볼 수 있게 준다.
- 기준 없이 시작했다면 지금 적고, 사후에 정했다고 밝힌다.

## 2. 요약보다 명령과 출력을 먼저 본다

에이전트의 자기 보고는 증거가 아니다.

- 보고를 받으면 요약을 읽기 전에 실행한 명령, 출력, 로그부터 연다.
  증거 위치가 없으면 그것부터 요청한다.
- 체크가 통과하면 증명한 것과 증명하지 않은 것을 나눠 적는다.
  초록불은 한 가지 성질만 말해 준다.
- 내 보고에도 같은 칸을 넣는다.
  기억이나 짐작으로 쓴 숫자는 넣지 않는다.

## 3. 감독할 힘을 지킨다

감독에 필요한 기술은 감독 대상에게 일을 맡길수록 줄어든다.
이것이 감독의 역설이다.
에이전트의 도움을 받아도 결과를 설명할 수 없다면 이미 책임을 넘긴 것이다.

- 내보내기 전에 바꾼 곳 몇 군데를 골라 "왜 이렇게 했는가"에 답해 본다.
  답하지 못하면 그 조각만 다시 이해한 뒤에 내보낸다.
- 에이전트가 대신 내린 결정과 가정을 나열하게 한다.
- 잊으면 곤란한 기술은 가끔 에이전트 없이 직접 한다.
  무엇을 더 이상 연습하지 않는지 주기적으로 적고, 놓을지는 의도해서 정한다.

## 4. 요약 말고 원본을 넘긴다

에이전트끼리 요약만 넘기면 세 번째 에이전트는 원본을 읽지 않은 상태가 된다.
이것은 개인 습관이 아니라 설계 원칙이다.

- 에이전트 사이에는 원본 문서와 데이터의 경로나 참조를 넘긴다.
  요약은 길잡이로만 붙인다.
- 흐름의 모든 단계가 원본에 닿을 수 있게 접근 경로를 유지한다.
- 하위 에이전트의 보고에도 근거가 된 원본 위치를 넣게 한다.
- 요약이 두 번 이상 손을 거쳤으면 원본을 다시 확인한 뒤에 쓴다.

## 보고 형식

맡길 때 이 형식을 요구하고, 내가 끝낼 때도 이 형식으로 쓴다.

```
상태: 끝 / 일부 / 막힘
완료 기준: 시작 전에 정한 것
증거: 실행한 명령과 출력 위치
증명한 것:
증명하지 않은 것:
혼자 정한 결정과 가정:
근거 원본: 경로나 참조
결정 필요:
```

## 내보내는 글

- humanizer 스킬이 있으면 결과 글에 적용한다.
- 가운뎃점, 줄표, 화살표 기호를 쓰지 않는다.
- 낱말을 하이픈으로 잇지 않는다. ID, 경로, URL, 명령, 코드 안의 하이픈만 둔다.
- 문장이 끝나면 줄을 바꾼다.

```bash
grep -nP '[\x{00B7}\x{2010}-\x{2015}\x{2190}-\x{21FF}]' <파일>
grep -nP '[가-힣A-Za-z]-[가-힣A-Za-z]' <파일>
```
