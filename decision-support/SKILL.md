# 큰 결정 돕기

무엇을 만들지, 왜 가치가 있는지, 누구에게 영향을 주는지, 무엇을 희생할지는 사람이 정한다.
에이전트는 사람이 스스로 판단할 수 있게 재료를 정리한다.
결정을 대신 내리는 것처럼 보이는 문서는 실패한 것이다.

## 순서

1. **내 가설을 먼저 적는다.**
   근거를 모으기 전에 결론이 무엇일 것 같은지 적는다.
   틀려도 된다.
   먼저 적어야 근거가 가설을 확인만 해 오는지 알 수 있다.
2. **"이게 틀리려면 무엇이 참이어야 하는가"를 적고 실제로 확인한다.**
   확신도를 말로 매기는 것보다, 실행할 수 있는 확인 하나가 훨씬 값지다.
   확인할 수 없으면 그렇다고 적는다.
3. **반대편을 세운다.**
   강한 입장일수록 반대 논거를 따로 만든다.
   다른 모델이나 새 컨텍스트의 서브에이전트에게 반대편을 논증하게 해도 된다.
4. **원본을 직접 본다.**
   결론이 기대는 숫자와 문서는 요약이 아니라 원본에서 확인한다.
5. **선택지를 결과로 쓴다.**
   고르면 무엇이 일어나고 무엇을 잃는지 적는다.
   추천이 있으면 하나만 표시하고 이유를 붙인다.
6. **모르는 것을 밝힌다.**
   확인하지 못한 것, 어림한 숫자, 문서끼리 어긋나는 곳을 따로 적는다.

## 결정 요청 형식

```
결정할 것: 한 문장
선택지:
  A. 고르면 일어나는 것 / 잃는 것
  B. 고르면 일어나는 것 / 잃는 것
추천: 하나와 이유 (없으면 없다고)
틀리려면: 추천이 틀리려면 무엇이 참이어야 하는가, 그걸 확인했는가
모르는 것: 확인하지 못한 것, 어림한 숫자
```

## 위험도에 따라

- 되돌리기 쉽고 비용이 작은 결정은 짧게 정리하거나 맡겨도 된다.
- 돈, 사람, 운영, 고객에게 영향이 가는 결정은 모든 칸을 채운다.
- 결과를 다른 사람이 감당하는 결정에서는 추론을 사람 손에 남긴다.
