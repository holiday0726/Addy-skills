# 큰 결정 돕기

무엇을 만들지, 왜 가치가 있는지, 누구에게 영향을 주는지, 무엇을 희생할지는 사람이 정한다.
모델이 아무리 좋아져도 이 질문은 사람의 것이다.
에이전트는 사람이 스스로 판단할 수 있게 재료를 정리한다.
결정을 대신 내린 것처럼 읽히는 문서는 실패한 것이다.

## 순서

1. **가설을 먼저 적는다.**
   근거를 모으기 전에 결론이 무엇일 것 같은지 적는다.
   먼저 적어야, 모은 근거가 가설을 확인만 해 오는지 알 수 있다.
2. **틀리려면 무엇이 참이어야 하는지 적고, 실제로 확인한다.**
   모델이 스스로 매긴 확신도보다, 실제로 돌려 볼 수 있는 확인 하나가 훨씬 값지다.
   확인할 수 없으면 그렇다고 적는다.
3. **다른 각도의 반론을 세운다.**
   강한 입장일수록 반대편 논증을 따로 만든다.
   여러 모델이나 새 컨텍스트의 서브에이전트에게 반대편을 맡겨도 된다.
   시간은 더 들지만 그 주제를 훨씬 많이 알게 된다.
4. **원본을 직접 본다.**
   결론이 기대는 숫자와 문서는 요약이 아니라 원본에서 확인한다.
5. **선택지를 결과로 쓴다.**
   고르면 무엇이 일어나고 무엇을 잃는지 적는다.
   추천이 있으면 하나만 표시하고 이유를 붙인다.
6. **모르는 것을 밝힌다.**
   확인하지 못한 것, 어림한 숫자, 문서끼리 어긋나는 곳을 따로 적는다.
7. **책임질 수 있는지 본다.**
   이 권고를 실행하고 유지할 사람 앞에서 그대로 설명할 수 있는가.
   설명할 수 없는 부분이 있으면 그 부분을 다시 확인하거나 모른다고 적는다.

## 결정 요청 형식

```
결정할 것: 한 문장
선택지:
  가. 고르면 일어나는 것 / 잃는 것
  나. 고르면 일어나는 것 / 잃는 것
추천: 하나와 이유 (없으면 없다고)
틀리려면: 추천이 틀리려면 무엇이 참이어야 하는가, 확인했는가
반론: 가장 강한 반대 논거
모르는 것: 확인하지 못한 것, 어림한 숫자
```

## 위험도에 따라

- 되돌리기 쉽고 비용이 작은 결정은 짧게 정리하거나 맡겨도 된다.
- 돈, 사람, 운영, 고객에게 영향이 가는 결정은 모든 칸을 채운다.
- 결과를 다른 사람이 감당하는 결정에서는 추론을 사람 손에 남긴다.

## 내보내는 글

이 스킬이 만드는 것은 사람이 읽는 글이다.
그래서 아래를 기본으로 지킨다.

- humanizer 스킬이 있으면 결과 글에 적용한다.
- 가운뎃점, 줄표(긴 것과 짧은 것), 화살표 기호를 쓰지 않는다.
- 하이픈으로 두 낱말을 잇지 않는다.
  ID, 경로, URL, 명령, 코드, 브랜치 이름처럼 원래 하이픈이 든 값만 그대로 둔다.
- 문장이 끝나면 줄을 바꾼다.
- 조어식 제목, 일상어 자리의 비유, 짜맞춘 대구, 아무도 하지 않은 말을 부정하며 시작하는 대조, 과장, 앞 문장을 되풀이하는 맺음을 쓰지 않는다.
- 다 쓴 뒤 금지 문자가 남았는지 검사한다.

```bash
# 가운뎃점, 줄표, 화살표
grep -nP '[\x{00B7}\x{2010}-\x{2015}\x{2190}-\x{21FF}]' <파일>
# 낱말을 잇는 하이픈
grep -nP '[가-힣A-Za-z]-[가-힣A-Za-z]' <파일>
```

두 번째 검사에 걸린 줄 가운데 ID, 경로, URL, 명령, 코드, 브랜치 이름만 남기고 나머지는 고친다.
