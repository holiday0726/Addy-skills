# 검증 루프

에이전트 덕분에 만드는 비용은 싸졌다.
병목은 코드를 쓰는 일에서, 이게 맞다고 확신하는 일로 옮겨 갔다.
검증 체계를 세우는 비용도 싸졌다.
어려운 것은 좋은 검증이 어떤 모습인지 아는 것이다.

## 1. 시작할 때: 검증됨을 먼저 정한다

끝난 뒤에 정하면 어떤 결과든 합리화하게 된다.
그래서 일을 시작할 때 적는다.

- 끝났다고 볼 실체: 테스트 통과, 측정값, 스크린샷, 로그, 트레이스
- 그 실체를 만드는 명령

## 2. 에이전트가 스스로 검증할 수 있게 한다

에이전트에게 확인할 수단을 쥐여 주면, 에이전트가 고치고, 돌리고, 결과를 읽고, 다시 고치는 일을 사람이 보기 전에 끝낸다.
좋은 결과를 내는 데 가장 중요한 조건 가운데 하나다.

- 끝에서 끝까지 도는 시험
- 입력을 바꿔 가며 성질을 보는 시험(속성 기반 시험)
- 실제 앱이나 화면을 조작해 보는 확인
- 숫자를 다시 계산하는 스크립트

모든 줄을 읽는 대신, 이런 루프를 만들고 그 증거를 검토한다.

## 3. 체크가 통과하면 증명 범위를 적는다

검증도 항복할 수 있다.
"내 결론을 뒷받침하는 증거가 있는가"가 어느새 "체크가 초록이 됐나"로 바뀐다.
테스트가 기능과 같은 실수를 품고 쓰였다면 둘 다 통과한다.
초록불이 말해 주는 것은 한 가지 성질뿐이다.

그래서 체크가 통과할 때마다 두 가지를 적는다.

- **증명한 것**: 이 체크가 실제로 확인한 성질
- **증명하지 않은 것**: 이 체크가 볼 수 없는 경우, 다루지 않은 입력, 돌리지 않은 환경

증명하지 않은 것을 하나도 말할 수 없다면, 그 체크를 아직 이해하지 못한 것이다.
이때는 가벼운 확인으로 넘어가지 말고 제대로 검토한다.

## 4. 놓친 것을 다시 점검한다

1. 스스로 "내가 놓친 게 있나?"를 묻는다.
   복잡한 작업 끝에 이 질문을 하면 두세 가지가 더 나오는 일이 잦다.
2. 위험이 크면 새 컨텍스트의 서브에이전트에게 결과와 완료 정의만 주고 비판하게 한다.
   내 결론을 함께 주면 그 결론을 확인해 오기 쉬우니 주지 않는다.
3. 나온 것을 고치거나, 고치지 않을 이유를 적는다.

기억날 때만 하지 않고, 루프에 넣어 매번 돌게 한다.

## 5. 끝낼 때 보고한다

요약을 쓰기 전에 실행한 명령과 출력부터 다시 본다.
기억이나 짐작으로 쓴 숫자는 넣지 않는다.

```
상태: 끝 / 일부 / 막힘
바뀐 것: 파일, 커밋, 배포 같은 실체
증거: 실행한 명령과 출력 위치, 측정값
증명한 것:
증명하지 않은 것:
놓친 것 재점검: 무엇을 물었고 무엇이 나왔는가
혼자 정한 결정과 가정:
결정 필요:
```

## 6. 체크를 강화한다

완료된 작업이 검토할 수 있는 속도보다 빨리 쌓이면, 세션을 더 늘려도 소용없다.
책임질 수 있는 것보다 많이 내보내면 그것은 검토가 아니다.
두 가지 가운데 하나를 한다.

- 반복되는 확인을 테스트나 훅으로 옮겨 사람 손이 덜 가게 한다.
- 속도를 줄인다.

검토는 공짜가 아니다.
일정에 별도 항목으로 잡아야 실제로 한다.

## 위험도에 따라 깊이를 고른다

- 되돌리기 쉬운 일: 1, 3, 5만 한다.
- 운영 반영, 삭제, 돈, 다른 사람이 결과를 감당하는 일: 모두 한다.
- 애매하면 무거운 쪽으로 본다.

이 결과를 유지보수할 사람 앞에서 설명할 수 없다면 내보내지 않는다.

## 내보내는 글

이 스킬이 만드는 것은 사람이 읽는 글이다.
그래서 아래를 기본으로 지킨다.

- humanizer 스킬이 있으면 결과 글에 적용한다.
- 가운뎃점, 줄표(긴 것과 짧은 것), 화살표 기호를 쓰지 않는다.
- 하이픈으로 두 낱말을 잇지 않는다.
  ID, 경로, URL, 명령, 코드, 브랜치 이름처럼 원래 하이픈이 든 값만 그대로 둔다.
- 문장이 끝나면 줄을 바꾼다.
- 조어식 제목, 일상어 자리의 비유, 짜맞춘 대구, 아무도 하지 않은 말을 부정하며 시작하는 대조, 과장, 앞 문장을 되풀이하는 맺음을 쓰지 않는다.
- 다 쓴 뒤 금지 문자가 남았는지 검사한다.

```bash
# 가운뎃점, 줄표, 화살표
grep -nP '[\x{00B7}\x{2010}-\x{2015}\x{2190}-\x{21FF}]' <파일>
# 낱말을 잇는 하이픈
grep -nP '[가-힣A-Za-z]-[가-힣A-Za-z]' <파일>
```

두 번째 검사에 걸린 줄 가운데 ID, 경로, URL, 명령, 코드, 브랜치 이름만 남기고 나머지는 고친다.
